# Latexy — Full-Stack Audit, 2026-07-25

Method: the whole stack was booted locally (Postgres + Redis + MinIO in Docker, backend/worker/beat/frontend
local, slot 1 → backend `:8030`, frontend `:5180`) and exercised against **real services with a real LLM key**.
Two real users were created through Better Auth. Nothing was mocked.

- **278 API operations** enumerated from the live OpenAPI schema and probed unauthenticated.
- **58-request cross-tenant IDOR matrix** (Alice creates every resource type, Bob attacks each one).
- **Real compile / ATS / optimize / cover-letter jobs** submitted, with a Redis `psubscribe *` sniffer
  capturing every event workers published.
- **Playwright** walked all ~40 pages authenticated and anonymous, capturing console errors, failed
  requests, WebSocket frames, blank screens; plus interactive flows, trial limits, share links and sad paths.
- **13 parallel code auditors** (146 agents) mapped every domain, then every finding was handed to an
  independent agent instructed to *refute* it. 133 raw → **119 confirmed, 14 refuted**.

Docs under `docs/` and `features-checklist/` were treated as untrusted and checked against source; the
drift is significant and is catalogued in §4.

---

## 0. Verdict

The engineering substrate is genuinely good, and that deserves saying plainly because it narrows where the
bugs are:

- **Authorization is solid.** The 58-request IDOR matrix found **zero** cross-tenant leaks — 403/404 across
  the board. Ownership is enforced consistently (`WHERE id = X AND user_id = caller`). Two endpoints that
  returned `200 []` for a foreign resume turned out to filter by `user_id` correctly. The auth chain
  validates Better Auth sessions against the `session` table including `expiresAt`; `require_admin` refuses
  a JWT claim and requires a verified email match.
- **The plain compile pipeline is excellent.** WS subscribe → replay → `job.started` → progress →
  live `log.line` streaming → `job.pdf_extracted` → `job.completed` with `page_count`, and a real 53 KB PDF
  delivered. Event names and payload fields match between publisher and reducer.
- **The DB schema is clean.** 41 Alembic revisions, `upgrade head` runs green, all three merge points
  resolve, and `--autogenerate` produced **no** column drift. Zero FKs left on `NO ACTION`.

The problems are concentrated in **the layer above** the substrate: features that were built, wired to the
UI, marked done — and then broken by one missing write, one deleted directory, or one response shape.
Four themes account for most of the severe findings:

| # | Theme | Consequence |
|---|---|---|
| A | Job artifacts/state are never persisted where readers look | Flagship AI feature returns no PDF; share links, apply, error history all dead |
| B | Money is not enforced | Plan quotas unenforced, BYOK keys unused, coupons not applied, double-billing possible |
| C | The production deploy path cannot start | Port, secret and WS-URL mismatches — compose prod is a guaranteed outage |
| D | Errors are swallowed instead of surfaced | CORS-less middleware errors, `.catch(() => {})`, provider errors mapped to HTTP 200 |

## 1. Runtime-verified findings (reproduced live in this session)

These are not static inferences — each was observed against the running stack.

### 1.1 — CRITICAL: "Optimize + Compile" completes successfully and produces no PDF

The flagship paid AI feature. Submitted a real `combined` job:

```
POST /jobs/submit {"job_type":"combined", ...}      -> 200  job_id=2c83b8fa…
GET  /jobs/2c83b8fa…/state    -> status=completed, percent=100
GET  /jobs/2c83b8fa…/result   -> 200  success=true, ats_score present
GET  /download/2c83b8fa…          -> 404  "PDF not found."
GET  /logs/2c83b8fa…              -> 404  "Log file not found"
GET  /download/2c83b8fa…/synctex  -> 404  "SyncTeX data not found"
```

The identical resume through the plain `latex_compilation` path returns a 53,764-byte PDF. Cause:
`orchestrator._run_latex_stage` (`backend/app/workers/orchestrator.py:522-639`) `rmtree`s
`TEMP_DIR/{job_id}` in its `finally` block and — unlike `latex_worker` — never caches the PDF/log/synctex
bytes into Redis. So every download route has nothing to serve.

Blast radius: the workspace optimize page, the anonymous `/try` funnel, `/jobs/batch`, quick-tailor and fork
flows. The user pays tokens, sees a score, and never gets a document.

**Fix:** cache `resume.pdf` / `.log` / `.synctex.gz` to Redis (as `latex_worker` does) *before* the
`rmtree`, or drop the `rmtree` until artifacts are persisted.

### 1.2 — CRITICAL: `Compilation` rows never reach `completed`, silently killing four shipped features

`Compilation` is created with `status="processing"` at submit (`job_routes.py:443`). The **only** code that
ever reconciles it to `completed` is a side effect inside `GET /jobs/{job_id}/result`
(`job_routes.py:769-799`) — and the frontend never calls that endpoint: it learns of completion over the
WebSocket and fetches the PDF from `/download/{job_id}`.

Live database state after a session of successful compiles:

```
 status     | count | with_pdf_path
 processing |    45 |             0
 completed  |     3 |             3
```

Rows from 2026-07-02 are still `processing`. The update also never sets `pdf_path`.

Everything gated on `Compilation.status == "completed"` is therefore permanently dead:

- **Share links** (`routes.py:1203`) — verified live: created a share link on a freshly compiled resume,
  `POST /resumes/{id}/share` → `200` with a `share_url`, then `GET /share/{token}` → **404** for both owner
  and anonymous visitor. The UI shows *"Something went wrong loading this resume."*
- **One-click apply** to Greenhouse/Lever (`application_routes.py:126`) → 422 "No compiled PDF found".
- **Compile error history** panel — always empty.
- **Bulk PDF export**, and every dashboard success-rate metric (always 0%).

**Fix:** have the worker update the `Compilation` row on terminal transition (and set `pdf_path`), rather
than relying on a client polling an endpoint the client never calls.

### 1.3 — HIGH: middleware error responses carry no CORS headers, so the browser can never read them

`CORSMiddleware` is registered **first** at `backend/app/main.py:120`. Starlette's `add_middleware`
*prepends*, so CORS ends up the **innermost** layer, and every middleware that short-circuits sits outside
it. Measured directly:

```
200 GET /health              -> access-control-allow-origin: http://localhost:5180   ✓
429 GET /subscription/plans  -> (no access-control-* headers at all)                 ✗   retry-after: 60
413 POST /compile (13 MB)    -> (no access-control-* headers at all)                 ✗
401 GET /compile             -> access-control-allow-origin present                  ✓   (route handler)
```

So the three errors real users hit most — rate-limited, file too large, request timed out
(`TimeoutMiddleware`, same mechanism) — reach the browser as an opaque `TypeError: Failed to fetch`. The
client cannot distinguish throttling from an outage and cannot honour `Retry-After`. This produced a flood
of misleading "blocked by CORS policy" console errors during the page walk, and the UI renders a generic
*"Failed to fetch workspace data"*.

**Fix:** register `CORSMiddleware` **last** so it is outermost.

### 1.4 — HIGH: auth-token race on mount silently breaks integration and plan state

Auth to FastAPI is `Authorization: Bearer <token>` held **in memory only**: `setAuthToken`
(`api-client.ts:868`) just assigns a field, and **nothing in the codebase ever writes
`localStorage.auth_token`** — so the fallback reads at `api-client.ts:887` and `:1781` are dead code.
`AuthSync` populates the token in a `useEffect` *after* the async Better Auth session resolves.

Any component fetching on mount therefore races it. `workspace/[resumeId]/edit/page.tsx:972,978,983`:

```ts
useEffect(() => { apiClient.getGitHubStatus().then(s => setGhConnected(s.connected)).catch(() => {}) }, [])
useEffect(() => { apiClient.getDropboxStatus().then(s => setDbxConnected(s.connected)).catch(() => {}) }, [])
useEffect(() => { apiClient.getCurrentPlan().then(setUserPlan).catch(() => {}) }, [])
```

`[]` deps — fired once, before the token exists, 401, and `.catch(() => {})` swallows it. No retry when the
session arrives. Observed live on the editor page: `2x 401 /github/status`, `2x 401 /dropbox/status`,
`2x 401 /subscription/current`, never succeeding, while `/resumes/{id}` returned 200 on the same page.
The same race produced a spurious `403 /download/{job}/synctex` (which returns 200 with correct auth).

User impact: a user who *has* connected GitHub/Dropbox sees them disconnected; a paying user's plan badge
falls back to free. Also hits `/settings` and `/admin` (which renders a raw `HTTP 401` string).

**Fix:** depend on the resolved session (`useEffect(..., [session])`) or gate fetches on token presence;
stop swallowing 401s.

### 1.5 — HIGH: `GET /analytics/me` is a hard 500 on every call

Reproduced every time. `analytics_service.py:153` and `:160` build **two separate**
`func.date_trunc("day", UsageAnalytics.created_at)` expressions, so SQLAlchemy emits `date_trunc($1, …)` in
the SELECT and `date_trunc($4, …)` in the GROUP BY. Postgres can't prove they're the same expression:

```
asyncpg.exceptions.GroupingError: column "usage_analytics.created_at" must appear
in the GROUP BY clause or be used in an aggregate function
```

The dashboard analytics panel fails for every user. (`/analytics/me/timeseries` works — 200, 7.8 KB.)

**Fix:** bind the expression to a variable and reuse it, or `group_by(literal_column("day"))`.

### 1.6 — HIGH: anonymous trial quota is not enforced

On a fresh `/try` context the UI showed **TRIALS LEFT 3**. I clicked Compile five times. The counter went
3 → 2 and then **stayed at 2**; the button was never disabled and no compile was ever refused. Five
compiles ran against a three-compile quota. A brand-new browser context resets to 3, so the fingerprint gate
is also bypassable by clearing storage.

Related, from the static pass: per-plan quotas in `SUBSCRIPTION_PLANS` (`config.py:262-412`) are advertised
and sold but **never enforced anywhere in the backend** — a free (₹0) account gets unlimited compiles and
unlimited LLM optimizations on the platform key.

### 1.7 — HIGH: BYOK settings page crashes for every signed-in user

Verified by shape. Backend returns a **dict**:

```json
{"success": true, "api_keys": [], "total_count": 0}
```

The Next proxy (`frontend/src/app/api/byok/api-keys/route.ts:19-23`) does `api_keys: data || []` — assigning
the *entire dict* to `api_keys` (and `data.length` is `undefined`, so `total_count` is always 0). The
consumer (`APIKeyManager.tsx:39`) then does `setApiKeys(data.api_keys)` and later `.map()` over it →
`TypeError`. The paid BYOK management UI is unusable regardless of whether any keys are saved.

### 1.8 — MEDIUM: `/ats/score` hands out a job id that can never be polled

`store_job_meta()` (`event_publisher.py:183`) is defined and unit-tested but **never called from any
production path**. `/ats/score`'s async branch (`ats_routes.py:215-236`) mints a `job_id` and returns
*"Use the job ID to check status and results"* — but never writes `latexy:job:{id}:meta`, which
`/jobs/{id}/state` and `/result` require. Verified: the job ran and published 4 events to
`latexy:events:{id}`, while `/jobs/{id}/state` returned **404 forever**. `/ats/deep-analyze` does it
correctly (`ats_routes.py:607-647`) — the inconsistency is inside one file.

The editor happens to use the synchronous `/ats/quick-score`, so the UI is mostly spared; API consumers and
`useATSScoring` (`async_processing: true`) are not.

### 1.9 — MEDIUM: nonexistent and malformed resume IDs silently bounce to `/workspace`

`/workspace/00000000-…-0000/edit`, `/workspace/not-a-uuid/edit` and
`/workspace/..%2F..%2Fetc%2Fpasswd/edit` all redirect to the resume library with **no "not found"
message**. No crash and no traversal leak (good), but a user following a stale bookmark gets no explanation.
`/r/` with an empty share token falls through to the raw Next.js 404 instead of the styled
"Link unavailable" page that invalid tokens correctly get.

### 1.10 — Environment/DX issues hit while bringing the stack up

- **`dev.sh` reports partial infra as healthy.** `is_infra_running()` greps only for `latexy-postgres`, so
  with Redis and MinIO down it printed *"Shared infra already running… Skipping"* and would have started the
  app against missing services.
- **Redis and MinIO host ports are hardcoded**, defeating the documented multi-slot/multi-clone workflow:
  `docker-compose.yml:71` (`"6379:6379"`) and `:91` (`"9000:9000"`) are not env-templated the way
  `DB_PORT` and `MINIO_CONSOLE_PORT` are, and `dev.sh:206-208` hardcodes them again. Both collided with
  unrelated local containers and had to be stopped to run this audit.

## 2. Confirmed critical findings from the code audit

Full machine-readable list (all 119, with evidence, repro and suggested fix):
`/tmp/findings_sorted.json`. Severities below are post-refutation, using the verifier's corrected rating
where it disagreed with the original auditor.

### Production deploy path cannot work (theme C)

These are all in the *release* path, so they are invisible in dev — and fatal on deploy.

1. **Backend image listens on 8000; everything targets 8030.** `backend/Dockerfile.prod:63-70` hardcodes
   uvicorn on 8000 while `nginx/nginx.conf:63`, the compose healthcheck and k8s probes all dial 8030.
   nginx 502s every `/api` request; k8s readiness never passes so pods never join the Service.
2. **`docker-compose.prod.yml` never passes `BETTER_AUTH_SECRET` or `JWT_SECRET_KEY`**, which `Settings`
   requires at import (`config.py:484-499`) — every backend/worker/beat container raises `ValueError` while
   importing config and exits. The stack cannot start. (k8s manifests do supply them.)
3. **`FASTAPI_ENV=production` is set, but no code reads it.** `config.py` reads `ENVIRONMENT`, which stays
   `"development"` in production — so `is_production_like()` is False and *all* prod hardening is off:
   `/docs`, `/redoc`, `/openapi.json` publicly enumerable; `CORS_ORIGINS` keeps its localhost defaults with
   `allow_credentials=True`; secret-strength checks skipped.
4. **nginx proxies the frontend to 5180; the prod frontend container serves 3000** (`nginx.conf:70` vs
   `frontend/Dockerfile.prod`) — every non-`/api` request 502s.
5. **Production WebSocket URL is wrong by construction.** `NEXT_PUBLIC_WS_URL=/ws` is baked in at image
   build, so the client connects to `/ws/ws/jobs`; nginx proxies `/jobs/ws/`; the real route is `/ws/jobs`.
   All real-time progress is dead in production. The nginx `/jobs/ws/` block is dead config.
6. **k8s nginx doesn't strip the `/api` prefix** (`location /api/ { proxy_pass http://backend; }`, missing
   trailing slash) — every REST call 404s on Kubernetes. Latent; compose happens to strip correctly.
7. **k8s ships committed Secrets with known weak passwords** (`latexy_password_123`, `redis_password_123`,
   `admin:flower123`) that `k8s/deploy.sh` applies as-is.

### Security

8. **LaTeX runs effectively unsandboxed.** The `shutil.which("docker")` branch
   (`latex_worker.py:272`, `orchestrator.py:546`) silently degrades to **local `pdflatex` in the Celery
   worker process** — which holds `DATABASE_URL`, `REDIS_URL`, provider API keys and
   `API_KEY_ENCRYPTION_KEY` in its environment, with `./backend` (including `backend/.env`) bind-mounted.
   Even the Docker path sets no network/memory/cpu/pids limits and no read-only rootfs.
   *(Note: the live run showed `restricted \write18 enabled`, the safe default — this is about the
   surrounding isolation, not `\write18` itself.)*
9. **The LaTeX injection blacklist is bypassable**, giving arbitrary host file read exfiltrated through the
   streamed compile log. Verified bypasses: `\makeatletter\@@input /path`, `\csname input\endcsname{…}`,
   `\write 18{…}` (with a space), `\openin1=…` (`latex_service.py:25-40`). Because log lines are streamed
   over the WebSocket, the file contents come straight back to the attacker.
10. **The `combined` job path never calls `validate_latex_content` at all** (`job_routes.py:387-412`), so
    even the weak guard is absent on that route — the literal `\write18{…}` and `\input{/etc/passwd}` forms
    reach pdflatex.
11. **`POST /optimize` and `POST /optimize-and-compile` are completely unauthenticated** LLM endpoints on
    the platform key (`routes.py:536-606`) — no trial counter, no plan check, no attribution.
12. **Two per-route limiters trust `X-Forwarded-For` unconditionally** (`ats_routes.py:59-64`,
    `scraper_routes.py:52-63`), contradicting `TRUST_PROXY_HEADERS` which the shared middleware honours
    correctly. One client rotating the header consumes the platform-wide deep-analysis budget.
13. **Body-size limit only inspects `Content-Length`**, so a chunked upload bypasses it and reaches an
    unbounded `file.read()`.
14. *(Mine, related to 12)* **`ai_routes.py` uses raw `request.client.host`** (lines 220, 317, 395, 494,
    933, 1507), ignoring `TRUST_PROXY_HEADERS` entirely. Behind nginx in production every anonymous caller
    collapses into **one shared 20/min bucket**, so anonymous AI features break globally under real traffic.

### Correctness / data

15. **AI summary cache key hashes only the first 500 chars** of the resume (`ai_routes.py:284-291`) — two
    users starting from the same shipped template collide, and user B is served summaries synthesised from
    **user A's resume**.
16. **Batch Tailor variants are never written.** No worker or route ever updates the forked
    `Resume.latex_content`, so every "tailored variant" is a byte-identical copy of the parent. Users pay
    for N optimizations and open N unchanged resumes.
17. **Invited collaborators cannot open the resume.** No REST resume endpoint consults `ResumeCollaborator`,
    so `GET /resumes/{id}` 404s for an invitee and the editor redirects them away before Y.js ever starts.
18. **Collaborator `role` is never enforced.** `/ws/collab/{id}` accepts any user with a
    `ResumeCollaborator` row regardless of role, so a "Viewer (read-only)" can apply arbitrary Y.js updates
    that persist and relay to all peers. The role selector is cosmetic.
19. **Anonymous share links are broken by construction** — always presign `shares/{id}/anon.pdf`, a key
    nothing ever writes.
20. **Cancelling a combined job triggers a full retry** (a second billed LLM call) and reports
    "internal error" instead of `cancelled`.
21. **`Compilation.ats_score` does not exist on the model** (`email_worker.py:163`) — the weekly digest task
    always raises `AttributeError` and is silently swallowed, so no opted-in user ever gets a digest.

### Billing (theme B)

22. **Per-plan quotas are never enforced** (see §1.6).
23. **BYOK keys are never used by the main optimize / quick-tailor flows** — the platform key always pays,
    which is the exact cost the BYOK plan exists to offload.
24. **Coupon discounts are never sent to Razorpay** — the user sees "20% off", is charged full price, and
    their one-time redemption is burnt. (Latent: nothing creates `CouponCode` rows yet.)
25. **Nothing prevents a second live Razorpay subscription** — a plan switch double-bills, and the app loses
    the pointer to the first subscription so `cancel_subscription` can't reach it.
26. **`cancel_subscription` reports success even when the Razorpay call fails** — the user is told they
    cancelled and keeps being charged.
27. **`GET /subscription/current` 404s for any user with 2+ subscription rows** (`scalar_one_or_none()` on
    an unlimited query) — normal after a retried or upgraded checkout. Billing page shows a permanent error.
28. **Webhook idempotency key is read from a body field Razorpay does not send**, so replay protection never
    engages.
29. **Team seat members keep pro-level access forever** after the owner's team subscription is cancelled.
30. **Anonymous trial use is consumed before the request is validated** — a 400 burns one of three free uses.
31. **Client-supplied `model` string is forwarded with no allowlist** — any subscriber can select the most
    expensive model in the catalogue, billed to the platform.

### Error surfacing (theme D)

32. **Every AI endpoint maps provider errors and rate-limit exhaustion to HTTP 200 with the input echoed
    back**, so the UI shows a convincing fake success.
33. **Server-sent WebSocket `{"type":"error"}` frames have zero listeners** (`ws-client.ts:216-221`) —
    `forbidden` / `rate_limited` / `invalid_request` are silently dropped and not even console-logged. This
    is what makes the WS auth bugs invisible instead of loud.
34. **`job.retrying` is published by workers but unhandled everywhere on the frontend**, freezing the UI
    silently for up to 10 minutes.
35. **`ws.onclose` never checks socket identity** (`ws-client.ts:167-175`), so every token change leaks a
    permanently-open socket per tab and can double-deliver every event into a non-idempotent reducer.
36. **The first WS subscribe never requests replay**, so `job.queued` is structurally unobservable and a
    fast job's `job.completed` can be missed entirely. Reconnect also resubscribes without `last_event_id`
    whenever no event arrived on the previous connection, dropping the whole outage window.
37. **No `ErrorBoundary` is mounted anywhere** despite `ErrorBoundary.tsx` existing.

## 3. Notable medium findings

Selected from the 51 confirmed medium items in `/tmp/findings_sorted.json`:

- Workspace resume list is hard-capped at 20 with **no pagination** — resume 21+ is unreachable, and a
  variant whose parent is "on page 2" vanishes from the grouping.
- Signed-out visitors get a **permanent spinner instead of a login redirect** on five pages; on
  `/workspace/[id]/edit` and `/optimize` the header is hidden too, so there is no way out but the back button.
- `middleware.ts` does **no auth gating at all** — route protection is 100% client-side. It also
  hard-codes the production hostname and runs a **blocking backend fetch on every request** for any other host.
- Six shipped pages are unreachable from the UI; the "Settings" menu item points at `/byok`, not `/settings`.
- The public portfolio exposes the **titles of every non-archived resume**, not just public ones.
- Compile-settings modal exposes latexmk flags and a TeX Live version the worker **silently discards**.
- Editor's Export dropdown exports the **last-saved DB copy, not the current buffer**; its "PDF" entry is a
  dead end.
- Image/OCR upload is advertised in the UI but the production image lacks **tesseract and poppler**.
- The delimiter state machine never flushes its hold-back buffer, **silently truncating ~14 characters** of
  generated LaTeX.
- Every streamed LLM token costs **6 sequential Redis round-trips**, including a full job-state `SETEX`.
- `handleSave` swallows backend validation errors and the title input has no length constraint, so the whole
  document can **silently fail to save**.
- A previously-rendered PDF is destroyed as soon as a new job starts, so a **failed compile leaves no preview**.
- WYSIWYG mode is persisted but the parsed document isn't — the editor is **stuck on "Parsing…" after reload**.
- `JobQueue`'s health footer renders literal **"undefined"** (`/jobs/health` returns none of the expected fields).
- Anthropic/OpenRouter BYOK keys can be stored and validated but are **consumed by nothing**; Gemini is
  advertised and unimplemented. Anthropic validation hardcodes one Claude 3 model id, so valid keys are rejected.
- `alembic revision --autogenerate` emits a migration that **DROPS the Better Auth `session`/`account`/
  `verification` tables** (no `include_object` filter) — reproduced empirically. A footgun, not a live bug.
- pgvector's HNSW index on `resumes.content_embedding` is **never used by any query**.

**Reverse drift** — substantial shipped work that no doc mentions: the guided form-based resume builder, the
feature-flag/admin system, frontend telemetry, and all the marketing pages.

Also: the "device fingerprint" is a random `localStorage` value and the trial never resets, which contradicts
the shipped help copy.

## 5. What I'd fix first

Ordered by user-visible damage per unit of effort:

1. **§1.1** — persist orchestrator artifacts before `rmtree`. Makes the flagship paid feature work at all.
2. **§1.2** — update `Compilation` from the worker. One fix restores share links, apply, error history and
   bulk export simultaneously.
3. **§1.3** — move `CORSMiddleware` to be registered last. One line; makes every operational error legible.
4. **§1.5** — reuse the `date_trunc` expression. One line; unbreaks the analytics panel.
5. **§1.7** — stop double-wrapping in the BYOK proxy. One line; unbreaks the BYOK page.
6. **§2.1–2.5** — the prod deploy mismatches. Cheap to fix, currently a guaranteed outage.
7. **§1.4** — gate mount-time fetches on the resolved session, and stop `.catch(() => {})` on 401.
8. **§1.6 / §2.22** — enforce quotas. Currently unbounded LLM spend on a ₹0 account.
9. **§2.8–2.10** — LaTeX sandboxing. Highest severity if the local-`pdflatex` fallback is ever hit in prod.
