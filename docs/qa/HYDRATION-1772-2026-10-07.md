# Hydration session-store candidate — 7 October 2026

This is a focused, opt-in candidate for issue #1772. It is intentionally
separate from the historical publication ledger: a clean run does not explain
or close the intermittent React hydration error 418 observed on workspace,
editor, and cover-letter surfaces.

## Candidate scope

The candidate contains only the reviewed `useSession` hydration gate,
`frontend/e2e/hydration-session-store.opt-in.ts`, and its dedicated
`frontend/playwright.hydration.config.ts`, plus the existing Cross-Browser
Quality workflow and its manifest/artifact assertions. The diagnostic baseline
is pinned to immutable source `2b84f7c2d04d85812249d718fdbae9bcd30db4a8`; it
does not read mutable `origin/main` state.

The normal CI path always sets `HYDRATION_AUTH_CLIENT_BASELINE=0` and runs only
the gated candidate. The baseline expected-error branch is a local diagnostic
mode, not a CI pass condition. Both modes use the same real `AuthSync` and
`apiClient` browser tree; the candidate checks the actual synthetic `/me`
request authorization after initial resolution, token refresh, retained 503
error, and recovery.

## Reproducible commands

From `frontend/` with Node 22 and installed dependencies:

```sh
HYDRATION_AUTH_CLIENT_BASELINE=0 \
  pnpm exec playwright test e2e/hydration-session-store.opt-in.ts \
  --config=playwright.hydration.config.ts --workers=1 --retries=0 \
  --trace=on --reporter=line --output=test-results/hydration-session-store
```

The baseline diagnostic is run separately, with the same command and
`HYDRATION_AUTH_CLIENT_BASELINE=1`; it must observe the expected React error
from the pinned pre-gate source and must never be counted as a green CI run.

## CI contract

The normal candidate runs inside the existing **Cross-Browser Quality** job,
with one worker, zero retries, `--trace=on`, and a dedicated
`test-results/hydration-session-store` artifact path. No new job or required
check name is introduced. The manifest test asserts the exact execution,
baseline guard, retry/trace settings, and artifact path so a future workflow
edit cannot silently remove or downgrade this gate.
