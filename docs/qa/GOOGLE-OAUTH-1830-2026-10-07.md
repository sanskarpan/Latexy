## Code fix

Better Auth and the public `/api/auth/providers` endpoint share one
server-side credential-pair check. The endpoint exposes only availability
booleans and existing public OIDC metadata, with `Cache-Control: no-store`.
Sign-in and sign-up fetch these capabilities at runtime, start with social
providers hidden, and ignore aborted discovery responses. Email/password,
passkey, and existing OAuth error/timeout recovery remain independent.

Callback recovery is also addressed: social requests return failures to their
sign-in/sign-up form while retaining the validated destination. Missing or
invalid OAuth state has a canonical login fallback. Forms map error codes to
bounded, actionable messages and never display provider-controlled
`error_description`. Better Auth does provide `/api/auth/error`; its production
default redirects to the homepage with query errors, losing the login context.
The defect is not a missing API route. Existing local-email verification and
account-linking safeguards are deliberately preserved.

The obsolete `NEXT_PUBLIC_OAUTH_GOOGLE_ENABLED` and
`NEXT_PUBLIC_OAUTH_GITHUB_ENABLED` flags are no longer required. Both members
of the matching server credential pair must be configured; missing or
whitespace-only credentials keep the provider unavailable.
